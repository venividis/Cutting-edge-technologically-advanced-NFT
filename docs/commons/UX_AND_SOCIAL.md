# A place worth returning to

## The product thesis

The NFT is an agent identity and control boundary. The human interface should be a useful
place to gather and accomplish something, not a cockpit of protocol acronyms or a perpetual
request to connect a wallet. This is a design thesis to test with people, not measured retention.

The return loop is **purpose -> contribution -> response -> useful result -> saved knowledge**.
It is not token-price watching, streak loss, an infinite feed or purchasable status.

## Six places, one consistent map

| Place | Human question | Meaningful action |
|---|---|---|
| Sanctuary | What deserves my attention? | Review a finite catchup and choose one intention. |
| Circles | Who is working on something I care about? | Join a purpose, ask, answer, share progress. |
| Work atelier | Can we turn this idea into a deliverable? | Write and inspect an explicit brief; link a real agreement. |
| Observatory | What is this agent actually allowed to do? | Read ownership, policy, coverage and evidence from contracts. |
| Tool garden | What capabilities exist and what do they cost? | See boundaries and reach the preserved protocol console. |
| Library | What do I want to keep? | Return to saved conversations and export device-local notes. |

Spatial navigation creates a memorable map, but never imposes a 3D maze. Controls remain
ordinary buttons and forms. The flat alternative is not a lesser product. Mobile users have
the same six destinations and functional composers.

The garden's architecture is procedural: gathering tables, workshop, archive, observatory,
central sanctuary and tool garden. No downloaded image disguises an inert mockup as a world.

## Rebuild social around intention and consent

A single global stream mixes problems that need different norms. Commons instead gives each
circle a shared purpose, visible rules, a steward and a transparent admission policy. Threads
have explicit types. A question has a direct helpful-answer relationship; progress can be
celebrated without becoming a reputation or investment signal; a work request can later link
to an exact escrow specification.

No NFT is required for circle participation. A controller can optionally speak with a checked
agent badge, but buying a token does not buy an EOA's history or social office. Wallet identity
is deliberately not labeled proof of humanness. The contract records the historical authority
of an agent-badged post rather than reassigning its author to each new token owner.

Muted authors disappear from a user's circle view and catchup, not from everyone else's world.
A report is an exported evidence file, clearly not an already-submitted moderation request.
Steward moderation is recorded and affects visibility, not permanent data availability.
Invitation-only means restricted writing, not encrypted reading.

## Progressive commitment

A newcomer can explore the map and rehearse the flow without network traffic or a wallet
prompt. Sample people and local posts are always labeled. Choosing live contracts requires
explicit configuration. Connecting a wallet asks only for connection. Publishing requires a
separate simulation/review/confirmation step. No hidden approval accompanies a social action.

The review should answer: what am I doing, who am I acting as, which contract and chain,
what value moves, what persists, and how can I cancel? Exact calldata is available without
forcing everyone to read it before understanding the action.

The Work atelier follows the same progression. A draft is not an offer. An offer is not accepted
work. Delivery is not settlement. Settlement is not a universal guarantee of quality. The UI
must preserve these distinctions as additional economic screens are implemented.

## Helpful return behavior, not coercion

Local drafts survive route changes; local state has a versioned, bounded restore path. Saved
references turn a feed into a personal collection of useful material. Catchup stops at five
items and can be marked read. In live mode it explicitly covers loaded conversations, not
all activity on a chain. A personal intention supplies continuity without points or penalties.

There are no notification-badge tricks, fictitious online counts, wealth leaderboards, paid
reaction boosts, random financial rewards or urgency timers. None of these choices proves
retention will improve; the value has to be observed in actual use.

## Pilot research plan (not yet executed)

Run a moderated pilot with newcomers, experienced crypto users, assistive-technology users
and agent builders. Ask each to find a circle, distinguish an example from a live record,
write a question, find a reply, inspect an agent's spending boundary, draft a work request,
review a transaction and explain what became public. Repeat on small screens and flat mode.

Primary measures should be first useful action, task completion, error/recovery rate,
comprehension of authority and permanence, useful replies received, and voluntary return to
unfinished work or saved knowledge. Measure gas/prompt abandonment separately from whether
people enjoy the map. Never claim that visual engagement alone demonstrates product value.

Any optional analytics in a future pilot needs explicit consent, minimized collection,
short retention and an inspectable schema. The shipped client sends no analytics. Do not log
post drafts, wallet signatures, private chat text or complete addresses as telemetry.

## Accessibility acceptance plan

WCAG 2.2 is the design reference, especially keyboard operation, visible focus, minimum target
size and alternatives to dragging. The shipped tests check navigation, target sizes and
horizontal overflow; they are **not a WCAG conformance audit**. Screen-reader narration,
contrast measurement, zoom/reflow, focus restoration across modal failures, multiple input
methods and actual reduced-motion settings require human/hardware validation.

Reference: https://www.w3.org/TR/WCAG22/

## Next integrations, only after their prerequisites

A restricted, revocable sponsored social session could remove gas prompts for a bounded set
of Commons calls. It must not grant agent-account execution, token approvals or arbitrary
call authority. EIP-4337/7702 and ERC-7715 are possible implementation inputs, not functionality
already shipped. A paymaster must carry clear cost/rate limits and an accessible fallback.

Private requests need encrypted consent-oriented messaging and key recovery. They must not
reuse the public composer. Agent discovery can use existing handles/registration manifests,
but transport endpoints should be verified before a client automatically visits them.

The 3D world can eventually display completed work and accepted contributions as spatial
changes. Those changes should derive from explicit facts, remain reversible in presentation,
and never imply that visual grandeur is financial trustworthiness.
